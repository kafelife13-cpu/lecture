# 주간 개인 피드백 계획 · v1

## 운영 목표와 분량
학생 약 100명의 채점된 과제·클리닉 기록을 학교·학년·시험범위·주차별로 묶는다. 한 학생에게 객관식 20문항(우선 오답 최대 10개 × 실제 유사문항 1 + 관련 개념문항 1), 핵심 개념 OX 20문항을 제공한다. 학교 프린트 빈칸은 별도 복습 코너로 제공하며 40문항 점수에 합치지 않는다. 클리닉 변형은 자작으로 표시하고 교사 검수 후 사용한다.

오답 10개 초과 시 반복 오답, 학교 핵심 개념, 최신 오답 순으로 선정하고 제외된 오답을 이월 목록에 남긴다. 10개 미만일 때만 이번 범위의 검수된 필수 개념 객관식으로 보충한다. 특정 오답에 연결할 유사·개념 문항이 없으면 다른 문항으로 숨겨 채우지 않고 부족분으로 표시한다. 문항 부족은 배부를 막으며 AI 초안을 검수 완료로 취급하지 않는다. 미제출·미채점은 오답으로 간주하지 않는다.

## 기존 시스템 재사용
- exams / exam_responses: 원래 문제·학생 답·제출 시각. 최신 응시 기준으로 현재 오답을 계산한다.
- odap_exam_tags / odap_mappings / odap_notes: 개념·유형·검증된 원문 연결·교사 피드백.
- odap_questions: 승인 문제은행. 키워드만으로 자동 연결하지 않고 원문별 reviewed_links로 평가 개념·판단 근거를 검수한다.
- odap_sources / odap_evidence: 학교 프린트와 작년 기출의 페이지·인용문·개념 근거. 기출 연도는 주차 시작 연도 - 1을 사용한다.
- odap/homework.js: 기존 전체 학생 순차 생성, 개별 실패 처리, 내보내기 흐름을 유지한다.
- 기존 OX는 1~10개 초안이며 기존 클리닉 완료 체크는 문항별 채점 기록이 아니다. 이 둘을 새 20문항 OX/보강 응시 이력과 혼동하지 않는다.

## 문항은행과 생성
문항은 학교, 학년, 범위, 개념, 원문 id, 유형, 정답, 해설, 검수 상태, 근거 id를 가진다. 동일 문항은 학생마다 복제하지 않는다. AI 생성은 학생 이름·연락처·성적 없이 원문 및 승인 근거만 전달하는 공통 초안 작업이다. 실제 유사문항은 기출·은행 검색으로 확보한다. 빈칸/OX/클리닉 변형은 초안→정답·근거·선택지 검수→승인→선정 순서다. 생성 실패 시 검수되지 않은 문항으로 대체하지 않는다.

## 매주 절차
1. 교사가 월요일 날짜로 주차·학교·학년·범위와 과제/클리닉 시험을 확정한다. 마감 시각 전 최신 채점 기록을 스냅샷으로 고정한다.
2. 학생별 우선 오답과 20+20 초안을 생성한다. 같은 입력은 같은 결과를 만들며 입력이 바뀌면 새 버전을 만든다.
3. 교사 화면에서 부족 문항·근거 미확인·정답 충돌을 먼저 해결한다. 검수 완료본만 배부한다.
4. 학생 앱에서 본인 주차 테스트를 1회 제출한다. 제출 중 재시도는 같은 결과를 반환한다. 제출 전 정답·해설은 서버에서 내려주지 않는다.
5. 제출 후 정답·해설·개념별 오답을 제공한다. 재복습은 별도 활동으로 기록하며 정규 주간 응시를 덮어쓰지 않는다.
6. 반복 오답 및 미응시를 다음 주 참고 자료로 전달하되 미응시를 개념 결손으로 단정하지 않는다.

## 저장·연결 설계
비공개 Drive: 문제/정답을 분리한 버전별 JSON, 출력용 자료, 학교 원본. Supabase: student_id, week_start, version, Drive 참조, SHA256, 상태, 작은 제출/채점 요약만 저장한다. 기존 대용량 body를 새 DB에 복제하지 않는다. 학생 접근은 기존 authenticate_user 결과의 실제 사용자 id로 제한하고 클라이언트 student_id를 신뢰하지 않는다. Drive 파일을 공개 링크로 배부하지 않는다.

현재 저장소의 Drive 외부화는 별도 시험판이며 운영 배포 확인이 없다. 이 작업의 로컬 엔진/인쇄/응시 API 계약부터 검증하고 실제 Drive 게이트웨이와 인증 서버가 확인된 후 앱 운영 연결한다. GitHub Pages에 개인 문제지·정답·토큰을 저장하지 않는다.

## 구현 단계와 통과 조건
1. 순수 선정·채점 엔진, 기존 내보내기 어댑터, 100명 배치 CLI, 학생용/교사용 인쇄 HTML, 가상 자료 테스트.
2. GitHub PR 자동 검사, 의존 Actions 업데이트, CodeQL 검사 설정, 문제 신고/검수 템플릿. 학생 자료는 CI에 넣지 않는다.
3. 운영 입력 샘플을 비공개로 연결하여 학교별 대표 학생 3명 검수. Drive 게이트웨이·서버 인증·원자적 주차별 1회 제출·본인 접근 테스트를 통과시킨다.
4. 교사 검수 후 전체 학생에게 주간 배부. 운영 연결 전에는 가상 데이터 시험판이라고 명확하게 표시한다.

필수 시험: 20+20 수량, 다른 학교/범위 차단, 작년 기출 연도, 중복/원문 재출제 차단, 부족분 배부 차단, 최신 정답으로 과거 오답 해소, 학생 답안 격리, 정답 사전 노출 방지, 중복 제출, 100명 배치 중단·재개.

## GitHub 적용 판단
공개 lecture 저장소에는 코드·계획·가상 fixture만 둔다. Actions 테스트, Dependabot의 Actions 업데이트, CodeQL, PR 및 Issue Form을 추가한다. 기존 CI/알림 workflow는 유지한다. Rulesets(필수 검사), Environments(운영 배포 제어), Secret scanning/push protection은 관리 API가 필요하므로 적용 여부를 별도로 기록한다. Projects는 개발 작업 관리에만 적합하며 학생 관리에 사용하지 않는다. Releases/Artifacts는 검증된 프로그램 배포에만 사용하고 개인 PDF/답안은 넣지 않는다. GitHub 예약 실행은 지연될 수 있으므로 주간 응시 제한·마감 판단의 기준으로 삼지 않는다.
