# 진단 분석 기준 (Claude 기준안 v0.1)

이 문서는 분석지의 모든 판단 규칙이다. 구현은 이 문서와 `taxonomy.json`을 따른다. 코드 값은 `taxonomy.json`이 원본이며, 이름·설명을 바꾸어도 코드는 바꾸지 않는다.

## 1. 입력 자료와 신뢰도

| 자료 | 위치(기존) | 사실로 쓸 수 있는 범위 |
| --- | --- | --- |
| 선택 답·정답·채점 | `exam_responses.answers`, 시험 문항 `answer` / 원본 연결 시 `odap_questions` | 학생이 무엇을 골랐는지, 맞고 틀렸는지 |
| 재응시 이력 | `odap_attempts` | 같은 문항을 몇 번, 언제 틀렸는지 |
| 사고 과정 | `exam_responses.raw.thoughts`, `_mock_wrong_notes` | 학생이 그렇게 적었다는 사실. 원인 해석은 아님 |
| 풀이 사진 | `cert_submissions` + `qa-files` Storage | 사진에 보이는 표시(밑줄, 지운 답, 풀이 흔적 유무) |
| 교사 원인 기록 | `odap_notes.error_type`, `note` | 교사가 확인한 원인 |
| 클리닉 누적 결과 | `odap_clinics`, `odap_homeworks`, 귀가 전 수행 체크 | 보강 과제 수행·정답 여부 |
| 문항 분류 | `odap_exam_tags`(같은 문항을 푼 전체 학생 공통) | 문항이 요구하는 개념·사고 유형 |
| 학교 프린트 근거 | `odap_evidence`(쪽·인용·개념, 승인된 것만) | 관련 설명·예문의 위치 |
| 문제은행 | `odap_questions`(status=approved) | 보강 후보 |

정답 키 충돌(`answer_key_conflict`)이 있는 문항은 진단 집계에서 제외하고 "정답 확인 필요"로 따로 표시한다.

## 2. 근거 등급 — 모든 진단 문장에 붙인다

| 등급 | 표시 | 조건 |
| --- | --- | --- |
| 확인 | `[확인]` | 채점 기록, 재응시 이력, 클리닉 결과, 교사 원인 기록, 사진에 보이는 사실 |
| 학생 진술 | `[학생 진술]` | 사고 과정·오답 노트에 학생이 적은 내용. 그대로 요약해 옮긴다 |
| 추정 | `[추정 · 상담 확인]` | 위 자료의 패턴에서 Claude가 해석한 원인. 반드시 상담 질문 1개를 짝지어 둔다 |

- 추정은 학생용 분석지에 사실처럼 쓰지 않는다. 교사용에만 싣고, 상담에서 확인되면 교사가 `확인`으로 올린다.
- 모든 진단 문장에는 근거 위치를 붙인다: `중간고사 7번(선택 ③, 정답 ⑤)`, `학교 프린트 「품사」 3쪽`, `문제은행 #id`.
- 근거가 없는 문장은 쓰지 않는다. 답 번호만으로 원인을 확정하지 않는다(기존 `clinic.sql` 원칙 유지).

## 3. 문항 유형 분류 (문항 기준, 학생 공통)

문항 하나에 `영역` 1개, `세부 개념` 1개 이상, `요구 사고 유형` 1~2개를 붙인다. 코드 목록은 `taxonomy.json`의 `areas`, `question_types`.

- 세부 개념은 학교 프린트의 단원·소제목 이름을 그대로 쓴다(예: `품사-관형사와 관형어`, `음운 변동-비음화`, `「농무」-화자의 정서`). 그래야 프린트 근거와 연결된다. `문법`, `문학`, `기타` 같은 큰 이름은 개념으로 인정하지 않는다(기존 SQL의 제외 목록과 동일).
- 요구 사고 유형은 "정답을 고르려면 무엇을 해야 하는가"로 정한다. 선지 하나하나가 아니라 문항 전체 기준이다.
- 분류는 교사가 확정한다. Claude/Codex가 자동 제안한 값은 `제안`으로 저장하고 확정 전에는 진단 집계에 쓰지 않는다.

## 4. 오답 원인 분석 (학생·문항별)

코드 목록은 `taxonomy.json`의 `error_causes`. 문항 하나에 주원인 1개, 필요하면 부원인 1개.

판정 순서:

1. 교사 원인 기록이 있으면 그 값 → `[확인]`.
2. 학생 진술이 있으면 진술을 원인 코드의 `확정 신호`와 대조한다. 진술이 확정 신호와 직접 일치하면 `[학생 진술]`과 함께 원인 코드를 `[추정 · 상담 확인]`으로 제안한다. 학생 진술만으로 `[확인]` 처리하지 않는다.
3. 진술이 없으면 선택한 오답 선지의 내용, 사진 흔적, 같은 개념의 다른 오답을 보고 원인을 `[추정 · 상담 확인]`으로만 제안한다.
4. 판단 근거가 없으면 `E00 원인 미확정`으로 두고 상담 질문만 만든다.

예외: `E10 단순 실수`는 사진이나 진술에 정답 판단 흔적이 있을 때만 쓴다. 근거 없이 "실수"로 처리하지 않는다.

## 5. 강점·반복 취약점·보완점 판정

집계 단위는 `세부 개념` 과 `오답 원인 코드` 두 축이다. 중간고사와 클리닉 누적 결과를 합산하되, 출처를 구분해 표시한다.

| 판정 | 조건 | 비고 |
| --- | --- | --- |
| 반복 취약점 | 같은 세부 개념 또는 같은 원인 코드로 **서로 다른 문항 2개 이상** 오답, 또는 같은 문항 **재응시 2회 이상** 오답 | 원인 코드 기준 반복은 `[확인]` 원인이 2개 이상일 때만 확정, 추정만 있으면 `반복 의심`으로 표기 |
| 보완점 | 오답 1회이며 반복 조건 미충족, 또는 과거 오답 → 최근 정답(`개선 중`) | `개선 중`은 강점이 아니라 보완점에 둔다 |
| 강점 | 같은 세부 개념에서 채점된 문항 **3개 이상**, 정답률 **80% 이상**, 최근 응시 오답 없음 | 고난도(`상`,`최상`) 정답 포함 시 앞에 둔다. 오답이 없다는 이유만으로 강점이라 쓰지 않는다 |
| 판정 보류 | 해당 개념 채점 문항 3개 미만 | "자료 부족"으로 표시 |

우선순위(분석지에 싣는 순서): 기말 범위 포함 여부 > 반복 횟수 > 고난도 오답 여부 > 최근성.

## 6. 학교 프린트·문제은행 연결

취약점(반복 취약점과 보완점) 하나마다 다음 3단계를 붙인다.

1. **개념 다시 보기**: 같은 세부 개념의 승인된 학교 프린트 근거(`odap_evidence`) 최대 2개. 쪽·인용을 그대로 표시한다.
2. **유사 유형**: 문제은행에서 세부 개념 일치 + 요구 사고 유형 일치, 난이도 `중`~`상`.
3. **심화**: 세부 개념 일치, 난이도 `상`~`최상`, 원래 문항보다 조건이 하나 더 있거나 다른 사고 유형.

### 보강 문항 선정 기준

- 필수: `status=approved`, 정답 검증됨, 세부 개념 일치, 학생이 이미 푼 문항·원 문항과 다른 문항(기존 fingerprint 중복 검사 재사용).
- 우선순위: 오답 원인 코드 일치(`odap_questions.body.error_types`) > 요구 사고 유형 일치 > 같은 작품·지문 > 같은 학교 > 최신 등록.
- 수량: 취약점당 유사 2 + 심화 1. 분석지 한 부는 상위 취약점 최대 5개, 보강 문항 최대 15개.
- 부족하면 새로 만들거나 중복으로 채우지 않고 부족 수를 그대로 표시한다(기존 원칙 유지).
- 원인 코드별 문항 형태 권장: `E01·E02`는 개념 확인 + 예문 판별, `E03`은 지문 근거 찾기, `E04`는 선지 분해형, `E05`는 발문 조건 표시형, `E06`은 <보기> 적용형.

## 7. 분석지 구성

교사용(상담용)과 학생용을 같은 데이터에서 만든다.

| 구역 | 교사용 | 학생용 |
| --- | --- | --- |
| 1. 요약(강점 1~2, 반복 취약점 상위 3, 보완점) | ○ | ○ (확인·학생 진술만) |
| 2. 문항별 오답 근거표(시험·번호·선택 답·정답·유형·원인·근거 등급) | ○ | ○ (추정 열 제외) |
| 3. 취약점별 프린트 근거 → 유사 → 심화 | ○ | ○ |
| 4. 추정과 상담 질문 | ○ | × |
| 5. 자료 한계(정답 충돌, 판정 보류, 보강 부족 수) | ○ | 간단히 |

상담 질문은 열린 질문으로 쓴다. 예: "7번에서 ③을 맞다고 본 근거는 지문의 어느 문장이었니?" 원인을 미리 말하지 않는다.

## 8. 아직 정해야 할 것 (선생님 확인)

- 기말고사 범위(단원·작품·프린트). 우선순위 계산에 필요하다.
- 첫 분석 대상 학생.
- `taxonomy.json` 코드 목록 확정(추가·삭제·이름 변경).
- 학생용 분석지 배부 여부. 우선은 교사용만 만들고 상담 후 학생용을 배부하는 것을 권장한다.
