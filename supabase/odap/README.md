# 오답연구소 서버 설치

## 클리닉 비슷한 유형 연습 (기본 정지)

기존 `migration.sql` 및 `identity-save.sql` 설치가 끝난 환경에서 **`clinic-practice.sql`만 별도로 적용**합니다. 기존 환경에서 migration 전체를 다시 실행하지 않습니다. 새 SQL은 트랜잭션 단위이며 재적용 시 설정·배정·풀이·신고를 보존합니다. 이 제작 작업은 로컬 합성 데이터 검사만 수행하며 운영 적용·배포는 포함하지 않습니다.

`odap_clinic_practice_settings`는 `singleton=true`인 한 행입니다. 초기값은 `enabled=false`, `allowed_student_ids='{}'`, `allowed_clinic_weeks='{}'`입니다. 별도 운영 검토 후 대상 학생 ID와 실제 `clinic_week` 문자열 목록을 모두 지정하고 enabled를 켜야 합니다. 끄면 이후 새 배정·학생 조회·제출을 막습니다. 진행 중인 RPC는 설정 행을 읽기 잠금으로 보호하므로 설정 변경은 해당 RPC의 종료를 기다릴 수 있습니다. 학생 앱에서 정지 응답을 받은 세션은 추가 호출을 멈추므로 다시 켠 뒤에는 새로고침 또는 재로그인이 필요합니다. 설정 변경 UI와 일괄 실행 버튼은 없습니다.

**답안 저장 트리거를 사용하지 않습니다.** 이전 버전의 `odap_clinic_practice_sync` 트리거와 함수도 이 SQL을 적용할 때 제거합니다. 표시용 행 하나를 쓰는 방식도 잠금·실패를 저장에 전파할 수 있어 채택하지 않았습니다. 이미 저장된 exam_responses가 처리 기준입니다. 학생 앱은 인증된 `list`로 기존 배정과 대기 수를 먼저 조회하고, 별도 `allocate` RPC로 최대 3문항씩 처리합니다. 두 요청은 각각 독립된 트랜잭션이며 list는 배정 함수를 호출하지 않습니다. 내부 배정·대기 계산 함수는 클라이언트가 직접 실행할 수 없습니다. 답안 저장 트랜잭션에는 이 기능의 후보 탐색·쓰기·잠금이 전혀 들어가지 않습니다. 배정의 일반 오류·query_canceled(57014)는 해당 작은 배정 요청만 취소하며, 이전 호출의 진행분과 기존 문항 조회는 유지됩니다.

배정 결과의 `response_key`는 최신 답안·저장 시각·시험 문항·과제 범위 설정을 식별합니다. open/answered/withdrawn은 다시 배정하지 않고, 후보 없음으로 skipped가 된 결과도 같은 입력에서는 처리 완료로 기억합니다. 따라서 다음 호출이 동일한 후보 없음 오답부터 반복하지 않습니다. 입력이나 범위 설정이 바뀌면 skipped를 다시 평가합니다. 후보 은행에 문항을 추가한 것만으로 기존 skipped를 자동 재탐색하지는 않으며, 이 경우 답안을 다시 저장해 평가를 갱신할 수 있습니다. 취소되어 행을 남기지 못한 오답은 `odap_clinic_practice_work`가 원래 답안과 진행분을 비교해 대기로 계산하므로 교사에게 누락되지 않습니다.

학생 앱은 준비된 문항을 먼저 보여 주면서 남은 배정을 이어갑니다. 자동 호출은 한 번에 최대 8회이며 연속 실패는 3회까지만 재시도합니다(실패 후 0.5초/1초 대기). 한도에 도달하면 짧은 안내와 **잠시 후 다시** 버튼을 표시합니다. 버튼은 남은 처리부터 이어가고, 화면을 다시 그리는 것만으로 실패한 자동 재시도가 무한 재시작되지 않습니다. 패드·미리보기·정지·로그아웃 보호는 동일합니다.

`coalesce(category,'school')='school'`이고 `clinic_week`가 허용 목록에 있는 학생의 시험별 최신 답안만 처리합니다. 시험 이름은 사용하지 않습니다. `odap_grade(...)=false`만 오답이며 배열·객체 답안을 지원합니다. 미입력·판정 불가는 배정하지 않습니다. 시험지별 문항마다 한 행을 남기므로 뒤에 입력한 시험지도 다음 앱 이용에서 추가됩니다. 학생이 아직 앱을 열지 않았다면 교사 집계에 배정 대기로 보입니다. 과거 제출 시험·본문 해시, 승인 은행 후보, 현재 과제 후보를 학생의 배정 RPC당 한 번 정리하여 그 호출의 최대 3문항에 재사용합니다. 은행 풀에는 ID·본문 해시·개념·유형만 보관하며 오답마다 원문 전체의 검증·정규식을 반복하지 않습니다. 처리할 대기가 없으면 풀도 만들지 않습니다. 같은 학생의 동시 allocate는 대기하지 않고 남은 수를 반환하며 조회는 독립적으로 가능합니다.

1순위는 기존 승인 은행입니다. 검수된 원문 연결과 개념이 없으면 `no_mapping`, 원문 정답을 시험 정답으로 채점한 결과가 true가 아니면 `mapping_conflict`, 원문 유형이 없으면 `no_type`입니다. `any:` 대안 정답과 `all:` 모두 서버 채점 함수를 사용합니다. 후보는 승인 상태, 선택지 다섯 개, 1~5 단일 정답, 본문·해설, 학교 일치(출처·본문 각각 공란 허용), 기존 원문 조건을 모두 만족해야 합니다. 자작·AI 문항, 연결 원문, 공백 제거 본문이 같은 시험 문항, 학생이 응답한 시험에 연결된 문항, 이미 배정된 문항은 제외합니다. 개념과 유형이 각각 하나 이상 겹치는 후보 중 개념 교집합 수 내림차순·ID 오름차순으로 하나만 고릅니다. 후보가 없으면 은행 사유는 `no_candidate`입니다.

2순위는 은행의 네 조건 중 어느 단계에서든 선정하지 못한 오답에 적용합니다. `category='homework'`, `clinic_school=학생 학교 이름`, 생성일이 설정의 `homework_since` 이상인 기말 과제를 검색합니다. 기본 homework_since는 설치 시점의 90일 전이며 기말 범위가 바뀌면 운영 담당자가 갱신해야 합니다. `homework_exam_ids` 기본값은 빈 배열입니다. 비어 있으면 시험 이름에 `기말`이 포함된 과제만 쓰고, ID 목록을 지정하면 이름 대신 해당 목록으로 현재 범위를 제한합니다. 학교·생성일 조건은 항상 적용합니다. 학교명이 이름에도 있어도 학교 판별은 명시된 `clinic_school`만 사용합니다.

영역 대응은 `odap_clinic_practice_domain` 한 함수에서 관리합니다. `고전소설(춘향전)→문학(고전소설)`, `현대시→문학(현대시)`, `고전시가→문학(고전시)`, `현대 국어 문법·중세 국어·한글 맞춤법→문법`입니다. 과제의 domain을 우선 보고 대응값이 없으면 type도 확인합니다. 클리닉 domain의 괄호 안 작품명이 과제 시험 이름에 포함되면 우선하고, 이후 생성일 내림차순·시험 ID·문항 순서로 하나를 선택합니다. **2순위는 같은 영역 수준의 유사성이며 유형 일치를 보장하지 않습니다.**

과제 후보는 본문·해설과 1~5 단일 정답, 그리고 비어 있지 않은 문자열 선택지 다섯 개 또는 text/passage의 순서대로 된 ①~⑤가 있어야 합니다. 선택지는 SQL의 `odap_clinic_practice_has_choices`에서 함께 검증하며, 누락으로 배정하지 못하면 `no_choices`를 남깁니다. 지문과 선택지가 없는 발문만으로 1~5 라디오를 만들지 않습니다. 원래 오답과 공백 제거 본문이 같은 문항, 제출한 시험의 모든 문항과 그 본문 복사본, 이미 배정된 같은 본문은 제외합니다. '오답만 입력'과 OMR은 맞힌 문항의 키가 없을 수 있어, 답안 키의 존재 여부로 미풀이를 추측하지 않습니다. 일부 입력만 저장된 시험도 보수적으로 전체를 제외합니다.

공백 제거 본문의 해시를 은행·과제 공통 중복 키로 씁니다. 과제 문항은 배정 시점의 원문을 `practice_body`에 보존하며 선택지를 생성하지 않습니다. 배열 대신 원문에 선택지가 있으면 이를 그대로 표시하고 1~5 답 번호를 제공합니다. 양쪽 후보가 모두 없으면 skipped로 남기고 은행 사유와 과제 사유(`no_domain`, `no_homework_candidate`, `no_choices`)를 함께 기록합니다. 사유별 수는 두 단계 설명이므로 합산하면 건너뛴 오답 수보다 클 수 있습니다.

학생은 본인 ID로 인증한 RPC만 사용합니다. 표 직접 접근은 차단합니다. 미제출 조회는 명시한 표시 필드와 PNG/JPEG data URI만 내보내며 정답·해설·출처·근거는 숨깁니다. 제출은 행 잠금 후 한 번 채점하고 `result`에 최초 결과를 보존해 문제은행 편집 후에도 재제출 결과가 달라지지 않습니다. 승인 취소·회수·선택지 누락 문항은 조회와 제출에서 제외합니다. 재입력으로 오답이 없어지면 다음 allocate에서 open/skipped만 retired로 전환하며 answered 기록은 유지합니다. retired 문항은 중복 배정 제한에서 빠집니다.

교사 메뉴는 세 번째 위치에 두고 데스크톱 사이드바에 세로 스크롤을 적용합니다. 주차별 표는 최신 답안의 오답 수와 배정·배정 대기·건너뜀·풀이·정답 수를 시험별·학생별로 보여 줍니다. 시간 초과로 처리하지 못한 허용 학생의 오답도 배정 대기에 포함하며, 대기 수를 조회할 때 후보 탐색은 실행하지 않습니다. 회수된 배정과 풀이도 누적 수에 남습니다. 건너뜀 사유를 학생별로 확인할 수 있고 신고를 처리할 수 있습니다. 문항 회수는 전체 주차의 영향 학생·배정 수를 먼저 확인하며 행을 삭제하지 않습니다. 대상 문항의 풀이·정답·신고는 보존합니다. RPC는 item `id`, 은행 `question_id`, 또는 공통 본문 `content_key`로 회수 대상을 찾으며, 어느 방식이든 해당 문항을 전역 차단합니다.

`odap_clinic_practice_blocks`에 은행 ID와 본문 해시를 보존합니다. 회수 후 다른 학생의 새 배정, 중복 과제, 은행 본문 편집 후 재배정도 차단합니다. 기존 withdrawn 기록도 재적용 때 전역 차단으로 이관합니다. 회수와 배정은 별도의 공유/배타 자문 잠금으로 경합을 막으며 답안 저장은 이 잠금을 사용하지 않습니다. list/submit도 전역 차단을 다시 확인합니다. 전역 차단을 해제하는 UI/RPC는 없습니다.

연습은 성적표·주간 과제 완료·등수와 연결하지 않습니다. 기존 재풀이·오답 OX·시범 자동 처리에는 연결하지 않습니다. 자료 부족, 잘못된 연결·분류, 승인 취소는 교사 검수가 필요합니다. 문장 의미 비교는 하지 않으며 은행은 개념·유형 태그, 과제는 영역 대응과 작품명으로 선정합니다. 본문 해시 중복 제거는 text가 같은 경우만 다루므로 text가 다른 의미상 중복은 남을 수 있고, text는 같지만 지문이 다른 문항은 보수적으로 하나로 취급합니다. 과제 후보 제외에는 현재 답안과 odap_attempts의 과거 입력을 함께 확인하므로 재입력으로 답을 지워도 이미 입력한 문항은 제외됩니다. 실제 데이터 규모의 지연·동시 접속 성능, 운영 인증·스키마 및 실기기 dialog/포커스는 별도로 확인해야 합니다.

로컬 검사: `node scripts/check-odap-clinic-practice.cjs`, `node scripts/check-odap-clinic-practice-ui.cjs`. 기존 설치된 PGlite로 실제 SQL을 메모리 DB에서 실행하며 합성 데이터만 씁니다. SQL 검사는 오답만 입력·선택지 누락·전역 회수·일반 오류와 57014·과제 4×50/12×67/24×50 규모 및 은행 2,000/오답 15 규모, 3개씩 진행 보존·순수 조회·취소 후 재개·교사 대기·후보 없음 재탐색 방지, 기존 네 조건의 변이 실패를 확인합니다. UI 검사는 자동 재시도 제한·기존 문항 유지·안내·수동 재개도 포함합니다. 시간 수치는 합성 PGlite 측정이며 운영 성능 보장이 아닙니다. UI 검사는 VM/가짜 DOM과 CSS 확인이므로 실제 브라우저·모바일 검사를 대신하지 않습니다.

기존 `users`, `exams`, `exam_responses`, `qa_schools`, `authenticate_user`를 사용합니다. 학생 계정을 복제하지 않습니다. 학생 제출 저장 함수가 먼저 설치되어야 새 클라이언트가 동작합니다.

1. 운영 DB 백업과 실제 스키마·고유 제약을 확인합니다.
2. `migration.sql`, `identity-save.sql`, `storage-and-schedule.sql`, `linked-data.sql`, `fast-sync.sql`, `fast-search.sql`, `search-index.sql` 순서로 적용합니다.
3. `odap-assets.ts`를 `odap-assets` Edge Function으로 배포합니다. Gateway JWT 검사는 유지하고 내부 `odap_rpc`에서 기존 계정을 매 요청 인증합니다. 서비스 키는 함수 환경 변수에만 보관합니다.
4. 비공개 문제은행과 원본을 이관하고 수량·원본 해시를 확인합니다. 문제·답안·학생 정보는 이 공개 저장소에 올리지 않습니다.
5. 교사 인증과 학생별 공개 자료 격리, Storage 접근을 확인한 뒤 웹 변경을 배포합니다.

문항은 검수 후 자료에 포함하며 자료 승인 후 해당 학생에게만 공개합니다. 예약 생성은 한국 시간 04:00에 실행하되 관리 화면의 자동 생성 설정이 켜져 있을 때만 동작합니다. 검수 명제가 부족하면 중복 문제로 채우지 않습니다.

한글 제작은 Windows의 별도 작업자가 `worker_claim` / `worker_finish`로 연결합니다. 제작 PC가 꺼져 있으면 작업은 대기합니다. 브라우저 인쇄와 PDF 저장은 별도로 가능합니다.

기존 이름 기준 고유 제약은 유지됩니다. 동명이인이 같은 시험에 제출할 때 기록을 덮어쓰지 않고 오류를 반환합니다. 구형 클라이언트 사용과 실제 제약을 확인한 뒤 ID 기준 고유 제약으로 전환해야 두 학생의 동시 제출을 지원합니다.

현재 규칙 OX는 참 명제(O), 빈칸은 명제 내 지정어를 사용합니다. AI 객관식 변형은 기존 Claude 함수를 이용합니다. 핵심명제 정규화 중복 검사이며 서로 다른 표현의 의미 유사도 모델은 아닙니다. 모든 생성 결과는 교사 승인 대기 상태입니다.
